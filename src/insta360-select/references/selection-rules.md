# 从覆盖、事件到故事和选镜

执行顺序：**看素材 → 事件记录 → 故事候选 → 按作用选镜 → 排成序列回看 → 必要时改故事/重选**。理论按需看 [依据](editorial-foundations.md)，具体正反判断看 [案例](selection-cases.md)。创意第一的方向不变；有用的视觉关系与停顿同样算贡献。

## 看：建立可追溯的覆盖与事件记录

以有意义片段为单位，不给整条两分钟文件只打一个分。每个事件记录 `eventId/sourceId/sourceInUs/sourceOutUs/eventGroupId`、可见事实、准备/动作/关键瞬间/结果/反应、景别/主体/运动方向/光线/可裁比例、关联片段、画面与声音各自的可用区间、成人风险和不确定性。`eventGroupId`只把真实同一事件归组，不代表所有同组镜头必有因果关系。

- 将直接看到/听到的事实与解释分栏。没有听到的对话不转成字幕，不凭表情断言人物内心；声音可单独选用，音频入出点不必等于画面。
- 覆盖报告按来源记录视觉区间、观察方式（连续/抽帧/缩略图）、音频区间/是否实际听过、未覆盖区间和要回看的风险。仅抽帧不能称全段已看，文件可读不能称音频已听；缺项可交部分日志，不假造全覆盖。
- 唯一失败、唯一结果、关键反应和因果桥梁先入候选池，即使轻微晃动/曝光不理想。随后检查隐私、清晰度及可读性，无法使用则明确缺口，不因唯一而豁免隐私或虚构替代结果。
- 对候选故事实际依赖的关键动作/反应，回看连续上下文；同一全景时刻多个取景保留同源时间关系。联系表只负责定位。

## 找：比较有证据的故事候选

通常提出2–3条真实不同的方向；素材只支持1条或尚无成立故事时如实写，不凑数。每条写：

`storyId | 一句话变化 | 目标观众 | 观看回报 | 视觉概念 | 开头四项 | 关键节拍及事件证据 | 结尾回报 | 分享理由 | 缺口/风险`

开头四项为 `knownContext/viewerQuestion/withheldInformation/payoffShotIds`。兑现必须指向真实候选片段，不把未来希望发生的事当答案。先给部分结果也可以，问题由“能否完成”转为“如何做到”。没有兑现则收窄承诺、换问题或换主线，不靠标题假造结果。安静日常可用观察/发现和细节呼应，不强加失败—成功曲线。

节拍关系用 `cause_effect / contrast / escalation / question_answer / action_reaction / time_ellipsis / spatial_context`，并给真实依据。视觉类比用 `kind=contrast, basis=associative`；同次反应用 `basis=observed_same_event`并关联同事件组；跨日因果若真实有证据可用 `documented_causal_link`及明确事件证据/事实依据，不能只因先后排列就断言原因。异时表情不得标真实反应，类比不能暗示未经观察的因果。比较证据是否足够、变化是否可理解/有记忆点、视觉概念是否有素材承托，再选择主线；不采用固定镜头分数或爆款分。

## 挑：同一职责候选之间比较

先赋作用 `hook/context/development/evidence/reaction/payoff/transition/pause`，再比较技术与视觉质量。同一镜可多作用，但必须说明具体贡献。

| 检查 | 每个入选镜头应回答 |
| --- | --- |
| 叙事/视觉贡献 | 在这个位置，为观众增加什么信息、理解、期待、情绪或视觉观念？不能只写好看/高级/电影感。 |
| 删除损失 | 删除后，下个事件、情绪、空间或节奏损失什么？普通铺垫也可能是精彩结果成立的条件。 |
| 关键瞬间与停留 | 价值集中在哪个动作/表情/结果？何时已被接收、该切出？保留结果辨认和真实反应时间，不固定每镜秒数。 |
| 独特性/重复 | 哪个备选已经做了相同工作？重复动作是否有递进或差异？ |
| 手机可读性 | 实际构图/裁切/头像/文字后，主体、动作对象和结果还能辨认吗？ |
| 相邻关系 | 与前后镜在动作、目光、空间、声音、构图或观念上产生什么？注明切点/方向及事实依据。 |
| 声音贡献 | 可否只用该段声音做J/L-cut或声桥？音频源和画面源分别可追溯吗？ |
| 视觉表达 | 景别/光线/运动/创意处理为什么适合这里？为视觉联想而留的镜头也要说明联想。 |

选镜表保留入选理由和未选备选/淘汰原因；对漂亮但重复的片段、技术一般却唯一的反应、必要铺垫尤其写清取舍，不为流程填空泛形容词。

## 排：序列回看再作取舍

选完先排纸面序列/低成本连续串联，在授权范围内回看。查故事是否成立、开头是否兑现、事实关系是否真实、结果是否看清、动作/信息/情绪节奏是否有变化。节奏是本轮设计，不要求所有片都快—慢—高潮。

缺铺垫就补具体上下文，重复就删/换镜，兑现不足就改问题/主线，快切打断关键动作就恢复必要过程；把变更写入 `sequenceReview`。只回看/补选受影响区段，不重扫有效日志或无故重新导出整批4K。未真实播放/未听音时只记录纸面或局部结论，不宣称完整声画已通过。若在剪辑阶段发现问题，由insta-edit退回明确 `shotIds/eventIds` 与缺口，不启动第二条并行主剪。

## 六项可审查输出

可合并在 `selection.json` 及一份短报告，不要求六套重复文件：①素材覆盖；②有证据的故事候选；③所选主线与开头/结尾/分享理由；④镜头及独立音频入出点、作用/贡献/连接；⑤备选与淘汰原因；⑥序列复查、缺项及回选修改。字段按 [交接约定](../../insta-cut/references/handoff.md)。只有镜头清单与故事判断，不等于已剪完或独立审片通过。
