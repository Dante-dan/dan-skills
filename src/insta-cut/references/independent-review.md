# 独立审片与按需分工

本参考用于制作计划、最终成片审阅及修改后的复审。独立审片是交付门槛，不是作者自评；用户对成片明确说 OK 是另一个独立状态。

## 按需编排，不为角色数量增加成本

主剪负责素材清单、选片与故事决策、时间轴、混音、导出及变更记录。按任务需要启动以下协作者，可由同一协作者承担相近工作，但**当前成片的制作参与者不能担任最终独立审片人**：

| 角色 | 输入与产出 | 可并行范围 |
| --- | --- | --- |
| 素材侦察 | 实际原片、原声、时间码 → 镜头日志、事件与情绪变化、成人风险区段 | 按互不重叠的源文件分工 |
| 故事编辑 | 镜头日志并回看关键原片 → 一条主叙事、备选切入点、删留理由及缺口 | 可与素材搜集并行，先不锁定最终镜头 |
| 素材与音乐研究 | 已发现的故事需求 → 有许可的 B-roll、音乐、音效候选与准确来源 | 只读搜集；主剪统一决定采用和落点 |
| 专项检查 | 当前渲染及跟踪记录 → 成人遮挡、技术或音频问题证据 | 已锁定的同一版本上按不同检查维度并行 |
| 独立审片 | 最终编码文件和可访问音频 → 带时间码的问题、结论及复审记录 | 与制作分离；可请求专项证据，不能以作者结论代替审阅 |

主剪串联依赖：先看原片和听原声，再找故事；故事方向明确后搜集填补实际缺口的素材；分镜和镜头筛选后才安排转场、文字、贴纸与音乐。粗剪锁定后做声音和视觉精修，导出后才进行最终审片。变更时间轴的协作者不能同时写同一工程；所有人只修改各自明确分配的文件。

优先复用已看过的素材日志、已核验的许可和已有通过版本的证据。修改当前版本后，旧审片通过结论不能自动继承。大项目可分段审阅，但最后仍须对**同一完整编码版本**完成全片的顺序播放与声音审阅。

## 独立审片的实际输入

交接最少提供：

- 当前交付 MP4 的绝对路径、文件名、大小和 SHA-256；影片目标、画幅及准确帧率。
- 简明故事意图、原片区段映射、成人出镜区段及本次改动。意图用于理解目标，不暗示应给通过结论。
- 完整可听音轨；需要比对现场声音时提供对应原片音频或时间码。
- 许可台账、技术检查结果以及头像/取景风险区段。作者的 QC 只作线索，不能代替独立复检。

先确认文件可读、hash 一致、能够查看完整影片并听到实际音轨。没有音频能力时，必须将“原声、混音、音乐与音效衔接”记为**未审**；不能从波形、响度数值或文字描述推断听感通过。不能完整播放时，不能只凭联系表判定叙事和节奏通过。可在能力可用时补审；未审项存在时总体为“待审”。

## 审什么，如何给出证据

| 维度 | 实际审阅内容 |
| --- | --- |
| 叙事与情绪 | 开头是否引出具体人物/好奇点；行动、反应与变化是否可理解；落点是否成立；外部素材是否误导为真实家庭经历 |
| 镜头与节奏 | 空间、动作方向、目光和因果是否连续；快慢变化是否有呼吸；重复镜头是否贡献新信息；B-roll 是否补充环境或情绪而非打断关键动作 |
| 文字与效果 | 人物介绍、动态排版、擦除、镂空或跟随文字等是否有叙事动机；读得清且停留足够；字幕不遮眼神；贴纸顺序符合动作与情绪，转场不过量 |
| 成人隐私 | 全部可辨认成人（含背景、反光、侧脸）是否用一致的纯动物 3D 头像可靠遮住；头像透明边、下巴、遮挡交叉、裁切边缘和转场是否漏脸；孩子真实面部不被误遮 |
| 画面 | 肤色自然、曝光和白平衡连续；全景拼缝、抖动、畸变、锐化和升采样限制是否可接受且如实记录 |
| 声音 | 实际听完：现场对话、笑声、脚步等是否保留；配乐是否抢人声；切点是否爆音或突兀；J/L cut、环境底、混响尾音、淡入淡出和换曲是否自然；音效是否对应动作且不过密 |
| 技术与素材许可 | 全片解码、真实画幅/时基、音画同步、头尾黑帧/静音、异常闪帧、导出字样；第三方素材作者、许可、署名与使用范围是否有可追溯证据 |

顺序播放整片后，在成人进出画、转头、快速运动、遮挡交叉、镜面/背景人物、贴边构图、变速及所有涉及头像的转场处，检查**实际编码文件的逐帧画面**。检测器和稀疏联系表只用于定位，不能排除一两帧漏脸；没有逐帧核查到的高风险区段须标“未审”。重大修改后重新确定风险区段，不能仅复用旧时间码。

每个问题指向当前成片的时间码（必要时加帧号）、可观察现象及具体修法，例如“00:14.60–00:15.70 成人下巴进入右边缘；更换手部特写或安全裁切，再逐帧检查这一段”。不要写只有“节奏差”“再高级一点”的空泛意见。区分影响交付的必须修复项和可选审美建议。

## 修改、复审与停止条件

1. 作者收到问题后修复，重新导出为新版本，计算新 hash，并说明每项修改对应的新旧时间码。不能修改审片记录把问题消掉。
2. 独立审片人首先核对**当前文件 hash**，逐项核实必须修复项，再检查修改对声音、节奏、头像和邻近剪点的影响；对当前完整文件重新顺序播放。仅审草稿或旧版不能给新版通过。
3. 成人漏脸、无法解码、明显音画不同步、严重失真/爆音或许可缺口等阻断交付；叙事混乱、关键情绪被打断、装饰干扰也须修到符合故事目标。不能为尽快通过自动降低标准。
4. 所有必须修复项解决、所有必需维度有实际审阅证据，独立审片人才能将当前 hash 标为“通过”。“满意”指当前版本达到交付标准，不是要求个人审美无限打磨。
5. 主剪为一轮工作设置实际的时间/渲染预算并记录；默认连续两轮完整导出仍未通过时先诊断共同原因。预算耗尽、工具不能听/看或修复依赖用户输入时保留文件与问题清单，状态为“待修”或“待审”，清楚交接原因。不得无穷自动渲染，也不得把停止伪装成通过。

审片可以推动制作先行，无须反复询问已授权的常规取舍。独立审片通过后可交付并备份，但**不得据此推断用户已确认成片 OK**。

## 最小审片任务与记录

任务可直接写成：

> 你没有参与本片制作。请实际顺序播放并听完 `{mp4_path}`，核对 SHA-256 `{hash}`，按本参考审查叙事、节奏、文字/效果、成人隐私、画面、声音、技术及许可。对成人高风险区段逐帧复检。作者意图与 QC 仅为背景。每项问题给成片时间码、观察和可执行修法；不能查看或听到的部分明确列为未审。仅在全部必需维度实际审阅、阻断及必须修复项全部解决后通过当前 hash；否则返回待修或待审。

每版只留一份精简报告，包含：`reviewer`（独立身份及未参与制作声明）、`file/path/sha256`、`coverage`（全片播放/音频/逐帧区段及方法）、`findings`（时间码、观察、严重性、修法）、`unreviewed`、`verdict`（通过/待修/待审）及 `reviewed_at`。复审附上所解决问题与当前证据，不堆积空白模板或虚假评分。

## 与用户确认及清理的关系

为每条成片分开记录：`independentReview`、`userApproval`、`jianyingCloudBackup`、`driveFinalBackup` 和 `driveOriginalBackup`；这些不是互相代替的完成标记。用户未明确确认当前成片 OK 时，`userApproval` 必须为 pending，保留本地原片，即便独立审片和云端归档已通过。

剪映云空间用于工程/关联素材及可用的成片备份，必须记录实际包含内容与上传完成证据；Google Drive 归档按 [Drive 归档](drive-archive.md) 核验实际远端文件内容。只有用户明确确认成片 OK，且对应原片、侧车和成片均按归档规范备份核验完成，才依据授权删除清单中本地原片；保留本地成片、云端原片及审片/许可记录。
