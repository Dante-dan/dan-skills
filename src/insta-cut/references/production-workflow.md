# 从原片到可播放故事

## 看原片：画面和声音一起建立素材地图

先检查下载完整性和实际规格；生成低清带源文件名/镜头号/时间码联系表，围绕动作与对话看连续片段。联系表只用于定位，不代替观看。听懂台词再写逐字字幕；ASR低置信、听不清的词不能脑补。记录：源in/out、动作/目光、原声、景别、运动方向、情绪变化、成人轨迹、可裁比例、原始帧率、质量风险。

全景同一时刻的不同取景是同一事件，不冒充先后发生；父母视角与孩子视角之间保留方向、轴线和声场。先抽低成本代理，再为选中段输出高质量取景，避免满盘中间片。

## 找素材：从真实内容里补齐表达

先从同一源片找环境全景、鞋与小手、树影、玩具、父母反应和动作余韵。需要外部图片、视频、纹理或音效时，再读 [素材来源](material-sourcing.md)。外部素材只有明确叙事职责才加入；风景不能替代缺失的真实事件证据。

## 编排脚本：一个具体变化，而不是标题串联

把故事写成“谁想做什么→做了什么→出现什么变化→最后留下什么”。可以冷开场再回溯、观察式顺叙、动作蒙太奇或声音引导；用实际素材支持的结构。先列候选故事，再选有完整动作/关系变化的一条，避免把所有可爱镜头塞进一片。

脚本/分镜共用一张镜头表即可，字段：

`shot_id | source in/out | timeline in/out | 画面动作/景别/取景 | 叙事作用 | 原声/音乐/音效 | B-roll理由 | 文字/技巧及动机 | 成人遮挡/风险 | 素材许可`

B-roll在脚本阶段提出，也可精剪时补入：先声后画建立空间、反应镜头解释情绪、细节压缩重复动作、空镜缓冲段落。不用无关库存镜头拖长片长。分镜写可执行的源时间码，缺关键镜头则调整故事而非假造。

## 分层精剪：先故事、后视觉包装

1. **结构粗剪**：暂去音乐和主题花字，观看能否理解人物、行动和变化。必要对白保留普通字幕；剪掉信息重复，不剪掉理解动作所需的前因和反应。
2. **节奏精剪**：给重要目光、触摸与回应留时间；连贯动作可短，情绪停顿可长。动作切、反应切、声画错位和空镜改变节奏，不以每两秒切一次作为标准。
3. **设计处理**：每个设计先写“为何此处需要它”。人物介绍放首次有意义的出场，回溯提示只在时间真正改变时出现，文字跟踪不遮脸，结尾装饰跟随动作完成。读 [技巧索引](techniques/index.md)，整片维持字体、颜色、运动方向和声音的一致语法。
4. **声音与音乐**：先对白/现场声和空间底，再选速度、音色、乐句适配的音乐。先试自然声版本判断音乐是否有帮助。换场可用环境声桥、音乐乐句收束或混响尾音；混响只给适合的尾音/转场，不能给所有对白加空间效果。
5. **调色与内部预览**：镜头曝光/白平衡连续，自然肤色，保护高光；检查夜景噪点和插入素材的色彩差。真实4K60与源质量限制分开记录。完成片头/尾帧、文字安全区、头像和混音后，冻结待审时间轴版本并生成完整内部预览；必要时生成带实际混音的低清审片拷贝，只放 `work/`，不作为正式交付。
6. **正式导出前独立审片**：未参与制作的agent按 [独立审片](independent-review.md) 看完当前完整预览、听完混音并对照必要原声，检查故事、节奏、效果动机、成人隐私和高风险逐帧。修复后更新版本与预览hash，重新独立审查；仅有旧版通过、联系表或无声观看均不满足门槛。能力不足则 `review_pending`，不得正式导出交付。
7. **正式剪映导出与回归检查**：当前时间轴独立审片通过后才从剪映正式导出。核对导出对应已审版本、实际画幅和时基、全片解码、文字/头像/效果、黑帧、音画同步、实际声音与AAC峰值。正式文件需播放及高风险逐帧回归，不能仅比大小或设置。发现内容错误需修改时回到步骤6，重新通过后再导出；最终编码与已审版本不一致不能交付。“发布”不包含未经授权的平台公开分享。

## 交付目录和版本

新批次示例：

```text
project/
  2026-10-20 cuts/       # 用户可播放成片/封面/简短交付说明
    故事名-竖屏-v01-4K60.mp4
    故事名-横屏-v02-4K60.mp4
  work/                 # 代理、草稿、中间片
  records/              # 分镜、来源许可、QC、审核、备份/用户确认清单
```

日期默认本轮开始剪辑的本地日期，拍摄日期记录在源片清单；跨日修订保留该批目录。多个日期故事可分不同批次，不能改日期让旧片看似新交付。旧成片不擅自迁移或覆盖；已有目录与日期规范不一致时，新版本按新规范输出，旧引用在明确迁移前保留。

每个交付保存已审时间轴版本/指纹、审片拷贝SHA-256（若使用）、正式MP4 SHA-256、两者的镜头/声音/效果映射、源依赖、规格、字幕与效果动机、许可、QC和工具分工。状态依次区分：`editing → review_pending → agent_approved_for_export → final_export → final_regression_pending → final_verified → backups_pending / awaiting_user_approval → cleanup_eligible → complete`。内容修改回到 `review_pending`；备份和用户确认可先后到达，但两者都不应由推断补齐。`agent_approved_for_export` 仅授权本次正式导出，不能替代最终编码检查、用户OK或公开发布授权。
