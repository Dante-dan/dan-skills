# 交付、双云备份与确认后清理

## 目录和备份内容

先用当前账号的Drive工具核对 `My Drive / Insta360` 和现有父链、同名文件；远端ID存项目清单，不能硬编码到公开技能。

后续原片使用独立目录 `My Drive / Insta360 / 原片 / YYYYMMDD / 内容`。`YYYYMMDD` 取素材**拍摄日**，不是上传日或剪辑日；按相机元数据和实际拍摄上下文确认，日期不明时先核实，不凭当前日期填入。“内容”表示该日的原始文件或素材子目录，不要求创建字面名为“内容”的文件夹。例如：

```text
My Drive / Insta360 /
  原片 /
    20260101 /
      VID_20260101_120000_00_001-Original /
        VID_20260101_120000_00_001.insv
        LRV_20260101_120000_01_001.lrv
```

同一原片的INSV分段/镜头配对、LRV及必要侧车放在一起，保留原始文件名。多拍摄日分别归档；成片、预览、工作视频和外部素材不混入“原片”。

成片使用独立目录 `My Drive / Insta360 / 成片 / YYYYMMDD / 人类可读的文件名.mp4`。日期沿用项目**制作日**，与本地 `YYYY-MM-DD cuts/` 对应；稍后上传或重新核验不改变归属日期，跨拍摄日影片在台账记录各原片来源。例如：

```text
My Drive / Insta360 /
  成片 /
    20260102 /
      公园寻宝记-漫画短篇-4K60.mp4
      追着晚风跑-纪实短篇-4K60.mp4
```

文件名优先用故事标题或清楚的中文主题；同主题多个独立版本可补充风格、横竖版、版本或准确的画质规格以区分。不要只用相机原始文件名、UUID或内部工程代号。最终文件名不保留“待审”等临时状态；预览、代理、工作中间片不作为成片放入此目录。Drive重命名或归档不需要重编码；台账仍绑定确切成片hash、本地规范文件与远端ID，所有本地成片继续保留。

原片和成片上传前，按已核对的父目录ID查询并复用各自的类别、日期及素材目录，避免同名重复；台账保存两者各自的远端父链。新规则用于后续归档，已有旧位置的完整备份继续按原ID复用，不因新结构重新上传或自行迁移历史文件；用户另要求整理旧目录时，再移动并更新清单、复核父链与内容版本。

新批次按 [日期组织](production-workflow.md#日期组织实际落盘与迁移) 记录拍摄日的原片/成片归属和制作日 `YYYY-MM-DD cuts` 成片批次；本地与Drive对应关系存清单，既有云端文件可通过ID索引归属，不为目录美观重复上传。Insta360云相册原片不删除。

剪映云空间备份可恢复草稿和它依赖的素材，并在当前客户端支持时保存最终成片；如果只能同步草稿，记录为草稿备份，不能声称最终MP4已备份。最终MP4仍需本地+Drive两份。检查实际登录、空间/额度和客户端当前功能，不把会员身份等同于同步完成，不为备份新购空间。

本用户当前家庭剪辑工作流已明确授权上述私有云备份，项目清单仍记录授权消息及实际私人目标空间；公开复用本技能、切换用户/账号或无授权的新项目不能继承这句话，先核实对应授权。使用云空间同步会上传草稿及其中的家庭素材，限私人空间和已授权项目，不创建团队邀请、公开发布或共享链接。备份授权不扩展为AI人像/AI视频处理上传授权。

## 成片与原片核验

1. **原片在剪辑开始前即启动归档**：下载完整且稳定，容器、双镜头及音频尾部通过后，先为原片/侧车建立文件名、路径、字节、SHA256/MD5、稳定stat与完整性清单；不要等待最终成片。后续选镜与制作持续补充源依赖、版本、最终MP4 hash及审核报告，原片备份进度与剪辑状态分开记录。
2. 先按现有远端ID/父链、文件名与内容版本以及本地传输清单/官方队列作幂等检查：已核验完整的文件复用证据，已排队的继续观察，不重复上传/建目录。将尚未归档的完整文件上传到已核对的Drive目录，或用已授权官方桌面同步流程排队，与剪辑并行。没有完成下载的原片不能归档为完整；已有错误/旧版本复用ID更新并复核当前内容。备份慢或暂时受阻不阻塞读取完整本地源片剪辑，仍记录未完成状态并保留本地原片。最终成片在审片及编码检查通过后再追加双云备份，不能把待审片当合格成片归档完成。
3. Drive证据需要实际远端ID、父目录、字节、未删除状态、修改时间/版本及内容哈希。优先服务端校验和；否则用受支持的完整独立下载重新算哈希。同步文件存在、排队、大小相同或完成通知都不能单独证明内容相同。服务端旧残片或旧剪辑不算备份完成。
4. 若当前连接器过滤哈希，且既有项目已独立验证某版本官方桌面**CLOUD元数据**校验字段，可把该字段作为辅助证据：必须与本次服务端ID、父目录、大小、修改时间毫秒完全一致，未删除/无tombstone，且与现算稳定源文件hash一致。与local-content缓存属性严格区分；不称它为独立网络下载。字段不明、版本变动或信息陈旧就保持未核验。
5. 用 [verify_archive.py](../scripts/verify_archive.py) 生成对比报告（它不上传/不删除）：参数为 `--local /absolute/clip.insv --remote-metadata /absolute/provider-metadata.json --expected-parent VERIFIED_PARENT --output /absolute/report.json`。元数据包含 `id,name,size,parents,trashed,sha256Checksum/md5Checksum`；保留证据来源和版本，不能为了让脚本通过编造字段。
6. 剪映云空间记录当前项目名/ID、版本/时间、上传完成状态、素材完整性；重新打开云草稿核对媒体可用、时长/轨道和当前效果。支持完整取回时，把云端草稿及依赖下载到独立临时目录，核对依赖清单/文件内容并验证恢复不依赖原始本地路径；只在原机器打开且可能由本地原片或缓存兜底，不能证明云端可恢复。无法隔离验证时将恢复性标为未验证，保留原片，不为测试移走或删除源片。不能把“本地保存草稿”当云端备份。若可取回云端MP4则核对内容hash，否则明确验证层级，不能冒充Drive级二进制校验。

传输/登录/额度/下载上限/网络受阻，保留文件、记录待办；已知不变的413/被阻下载不重复尝试或绕过。没有当前可操作界面或连接器时不能宣称云空间完成。CapCut官方云空间帮助可作产品概念参考，但不证明国内剪映当前功能/额度，应以实际客户端为准：[官方云空间帮助](https://www.capcut.com/help/capcut-pro-cloud-storage)（2026-10-20查阅）。

并行归档台账区分 `not_started / queued / uploading / uploaded_unverified / content_verified / blocked`，存当前源hash/稳定stat、远端ID/版本、任务/队列标识与检查时间。制作期间不修改源片内容；源文件变化则旧内容核验失效，重新确认完整性与新版本。并行启动不代表提前获准清理：备份排队或上传结束都不满足删除条件，用户明确接受当前成片且下列备份门槛全部通过前始终保留本地原片。

## 大原片与磁盘余量

macOS APFS 同卷复制可先试系统 `cp -nc` 为官方同步目录创建独立的写时复制文件；先用一个小侧车验证支持，再复制完整原片。只对已核验完整、稳定的源操作，不覆盖已存在目标，不使用硬链接，不修改源内容。逐文件比较字节、SHA256与复制前后的源stat，记录实际剩余空间和规范日期目录；失败时保持原片，不自动退回会耗尽磁盘的普通大复制。文件系统克隆节省本地重复占用，不等于完成云端备份；上传还需官方队列与远端内容核验。后续释放本地缓存只用官方“释放空间/仅在线”，不unlink同步文件。

官方 Apple FileProvider 的只读文件状态可辅助区分 `isUploading`、`isUploaded`、暂停/排除；它们只证明系统传输状态，不能代替Drive真实远端ID、版本与内容哈希。Drive内部DB暂未出现文件而FileProvider已标上传中，应记录 `uploading_unverified`，不立即重复上传或重建文件夹。Lost & Found先保全完整副本，结合目标文件的具体日志判断离线、网络超时或其他实际原因；没有权限错误证据就不改ACL/权限，不把旧远端残片当完整备份。

实现与字段语义参考：[Apple：APFS文件克隆](https://developer.apple.com/documentation/foundation/about-apple-file-system)、[FileProvider isUploaded](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemprotocol/isuploaded)、[isUploading](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemprotocol/isuploading)。系统命令选项仍以本机 `man cp` 为准，不能把APFS概念当当前目标卷一定支持的证明。

## 用户确认是单独的清理门槛

审片agent通过之后向用户交付可播放当前版本。`userApproval`记用户明确OK的消息日期/引用、对应片名/版本和hash；“继续”“上传好了”、旧版认可或助手自动提醒都不是当前版本验收。用户说片子有问题意味着本版未被接受，不能继承旧清理授权。

只有下列条件全部满足才成为 `cleanup_eligible`：

- 当前版真实解码/声画/头像检查和独立审片通过；
- 用户明确确认对应成片版本OK，后续影响验收的修改须再次确认；
- 关联原片与侧车、最终MP4的Drive内容已核验，剪映云空间备份已验证；
- 源文件自核验后未变化，所有本地成片可用且保留。

随后按白名单移除**同步目录之外**对应本地原片和可重建工作视频，保存清理日志，不广泛递归删日期目录。若用户本轮另明确允许备份后移除本地成片，只绑定已认可的当前版本及其核验完成的备份；不把它推广到旧成片或尚未验收的新片，项目单独记此例外，技能默认仍保留本地成片。不能unlink Drive同步路径释放缓存，会传播云端删除；只能用官方“释放空间/仅在线”功能。未关联的原片不纳入清理。

## 监控接续

已有半小时检查继续使用原任务，不重建。核对实际消息投递、文件检查和远端证据，不只看调度启用。将后台提示词同步为最新“用户确认+双云备份+原片Drive内容核验”规则。仅归档任务不自行重剪；等待用户确认时不标complete、不自行删除、不每轮重复索取确认。完成全部条件和已授权清理后才结束原监控。
