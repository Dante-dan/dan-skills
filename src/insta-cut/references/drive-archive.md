# 交付、双云备份与确认后清理

## 目录和备份内容

先用当前账号的Drive工具核对 `My Drive / Insta360` 和现有父链、同名文件；远端ID存项目清单，不能硬编码到公开技能。

后续原片使用独立目录 `My Drive / Insta360 / 原片 / YYYYMMDD / 内容`。`YYYYMMDD` 取素材**拍摄日**，不是上传日或剪辑日；按相机元数据和实际拍摄上下文确认，日期不明时先核实，不凭当前日期填入。“内容”表示该日的原始文件或素材子目录，不要求创建字面名为“内容”的文件夹。例如：

```text
My Drive / Insta360 /
  原片 /
    20260101 /
      VID_20260101_120000_00_001-Original /
        VID_20260101_120000_00_001.insv
        LRV_20260101_120000_01_001.lrv
```

同一原片的INSV分段/镜头配对、LRV及必要侧车放在一起，保留原始文件名。多拍摄日分别归档；成片、预览、工作视频和外部素材不混入“原片”。

成片使用独立目录 `My Drive / Insta360 / 成片 / YYYYMMDD / 人类可读的文件名.mp4`。日期沿用项目**制作日**，与本地 `YYYY-MM-DD cuts/` 对应；稍后上传或重新核验不改变归属日期，跨拍摄日影片在台账记录各原片来源。例如：

```text
My Drive / Insta360 /
  成片 /
    20260102 /
      公园寻宝记-漫画短篇-4K60.mp4
      追着晚风跑-纪实短篇-4K60.mp4
```

文件名优先用故事标题或清楚的中文主题；同主题多个独立版本可补充风格、横竖版、版本或准确的画质规格以区分。不要只用相机原始文件名、UUID或内部工程代号。最终文件名不保留“待审”等临时状态；预览、代理、工作中间片不作为成片放入此目录。Drive重命名或归档不需要重编码；台账绑定唯一文件名、本地规范文件与可用远端ID；本地成片默认保留，用户明确授权清理的版本按本次范围处理。

原片和成片上传前，按已核对的父目录ID查询并复用各自的类别、日期及素材目录，避免同名重复；台账保存两者各自的远端父链。新规则用于后续归档，已有旧位置的完整备份继续按原ID复用，不因新结构重新上传或自行迁移历史文件；用户另要求整理旧目录时，再移动并更新清单、按唯一文件名复核新目录。

新批次按 [日期组织](production-workflow.md#日期组织实际落盘与迁移) 记录拍摄日的原片/成片归属和制作日 `YYYY-MM-DD cuts` 成片批次；本地与Drive对应关系存清单，既有云端文件可通过ID索引归属，不为目录美观重复上传。Insta360云相册原片不删除。

剪映云空间备份可恢复草稿和它依赖的素材，并在当前客户端支持时保存最终成片；如果只能同步草稿，记录为草稿备份，不能声称最终MP4已备份。最终MP4仍需本地+Drive两份。检查实际登录、空间/额度和客户端当前功能，不把会员身份等同于同步完成，不为备份新购空间。

本用户当前家庭剪辑工作流已明确授权上述私有云备份，项目清单仍记录授权消息及实际私人目标空间；公开复用本技能、切换用户/账号或无授权的新项目不能继承这句话，先核实对应授权。使用云空间同步会上传草稿及其中的家庭素材，限私人空间和已授权项目，不创建团队邀请、公开发布或共享链接。备份授权不扩展为AI人像/AI视频处理上传授权。

## 云端备份按唯一文件名核对

当前用户2026-10-21明确选择轻量规则：**保证文件名唯一，在实际云端目标目录核对文件名即可**。适用于Google Drive原片、侧车、成片和剪映私人云空间草稿/素材，覆盖此前内容哈希和恢复下载要求。后续不反复比对大小、修改时间、版本或哈希，不读Drive内部CLOUD校验字段，不为验证重新下载、恢复草稿或播放云端文件；不自动调用 `verify_archive.py`。该脚本只保留为用户以后另行明确要求内容校验时的可选工具。

1. 完整本地原片确认后，即按上面的日期目录启动原片/侧车备份，与剪辑并行；本地素材完整性、剪辑QC和独立审片照常执行，它们不是云备份核验。
2. 上传前按实际目标云目录查询完整文件名。命名包含日期、片名/素材名及必要版本，唯一绑定一个本地来源；同一名称的已备份项直接复用，不再次上传。新剪辑版本用新的版本后缀，不用同名覆盖不同版本。INSV/LRV保留唯一相机原名及配对关系。
3. 在实际云端目录中找到唯一同名项后，记录目录、完整文件名、检查时间和可用的远端ID，状态为 `name_verified`。核对一次后复用记录，不在每轮重新检查。多个同名项时先通过明确命名区分，不能随便选一个称已核对，也不擅自删除云文件。本地同步路径或上传队列名称不代替实际云端文件名。
4. 剪映草稿与依赖素材通过客户端上传到私人云空间；核对草稿/素材的唯一名称即完成本用户要求的备份核验，不再下载验证完整素材包。记录实际做过的文件名核对，不把它描述成哈希一致或已实测恢复。
5. 已有历史内容校验报告继续保留，直接复用，不为新规则重复上传或重复核验。用户明确确认当前成片且对应唯一文件名已核对后，按下节的授权范围清理本地。

并行台账区分 `not_started / queued / uploading / name_verified / blocked`；记录唯一名称、本地来源、实际云目录和检查时间即可。已排队就继续原传输，不重复提交；网络或登录受阻时记真实待办。无需为本用户的备份验收另算hash、下载或做恢复测试。原片/侧车、成片和草稿的备份进度分别记录。

## 大原片与磁盘余量

macOS APFS 同卷复制可先试系统 `cp -nc` 为官方同步目录创建独立的写时复制文件；先用一个小侧车验证支持，再复制完整原片。只对已核验完整、稳定的源操作，不覆盖已存在目标，不使用硬链接，不修改源内容。记录复制成功、实际剩余空间和规范日期目录；失败时保持原片，不自动退回会耗尽磁盘的普通大复制。文件系统克隆节省本地重复占用，不等于完成云端备份；备份核对按实际云端目录的唯一文件名规则执行。后续释放本地缓存只用官方“释放空间/仅在线”，不unlink同步文件。

官方 Apple FileProvider 的只读文件状态可辅助区分 `isUploading`、`isUploaded`、暂停/排除；它们只辅助观察传输，最终按实际云端目录的唯一文件名核对。客户端仍显示传输时记录 `uploading`，不立即重复上传或重建文件夹。Lost & Found先保全完整副本，结合目标文件的具体日志判断离线、网络超时或其他实际原因；没有权限错误证据就不改ACL/权限，不把旧远端残片当完整备份。

实现与字段语义参考：[Apple：APFS文件克隆](https://developer.apple.com/documentation/foundation/about-apple-file-system)、[FileProvider isUploaded](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemprotocol/isuploaded)、[isUploading](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemprotocol/isuploading)。系统命令选项仍以本机 `man cp` 为准，不能把APFS概念当当前目标卷一定支持的证明。

## 用户确认是单独的清理门槛

审片agent通过之后向用户交付可播放当前版本。`userApproval`记用户明确OK的消息日期/引用、对应片名/版本和hash；“继续”“上传好了”、旧版认可或助手自动提醒都不是当前版本验收。用户说片子有问题意味着本版未被接受，不能继承旧清理授权。

只有下列条件全部满足才成为 `cleanup_eligible`：

- 当前版真实解码/声画/头像检查和独立审片通过；
- 用户明确确认对应成片版本OK，后续影响验收的修改须再次确认；
- 关联原片与侧车、最终MP4及剪映云草稿/素材的唯一文件名已核对（`name_verified`）；
- 清理路径与授权清单对应；本地成片默认保留，用户另授权删除时仅处理明确范围。

随后按白名单移除**同步目录之外**对应本地原片和可重建工作视频，保存清理日志，不广泛递归删日期目录。若用户本轮另明确允许备份后移除本地成片，只绑定已认可的当前版本及其核验完成的备份；不把它推广到旧成片或尚未验收的新片，项目单独记此例外，技能默认仍保留本地成片。不能unlink Drive同步路径释放缓存，会传播云端删除；只能用官方“释放空间/仅在线”功能。未关联的原片不纳入清理。

## 监控接续

已有半小时检查继续使用原任务，不重建。核对实际消息投递、文件检查和远端证据，不只看调度启用。将后台提示词同步为最新“用户确认+双云唯一文件名核对”规则。仅归档任务不自行重剪；等待用户确认时不标complete、不自行删除、不每轮重复索取确认。完成全部条件和已授权清理后才结束原监控。
