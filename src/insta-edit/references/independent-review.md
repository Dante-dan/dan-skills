# 独立审片与按需分工

本参考用于制作计划、待审版本的独立审片、修改后的复审和另行编码后的回归。**剪辑完成 → 可从剪映原生导出待审预览 → 当前完整实际声画通过独立审片与编码检查 → 标为合格成片并交付**。未通过的原生导出只是一份待审预览，不是合格成片。独立审片不是作者自评；用户对成片明确说 OK 是另一个独立状态。

## 按需编排，不为角色数量增加成本

主剪负责素材清单、选片与故事决策、时间轴、混音、导出及变更记录。按任务需要启动以下协作者，可由同一协作者承担相近工作，但**当前成片的制作参与者不能担任最终独立审片人**：

| 角色 | 输入与产出 | 可并行范围 |
| --- | --- | --- |
| 素材侦察 | 实际原片、原声、时间码 → 镜头日志、事件与情绪变化、成人风险区段 | 按互不重叠的源文件分工 |
| 故事编辑 | 镜头日志并回看关键原片 → 一条主叙事、备选切入点、删留理由及缺口 | 可与素材搜集并行，先不锁定最终镜头 |
| 素材与音乐研究 | 已发现的故事需求 → 有许可的 B-roll、音乐、音效候选与准确来源 | 只读搜集；主剪统一决定采用和落点 |
| 专项检查 | 当前渲染及跟踪记录 → 成人遮挡、技术或音频问题证据 | 已锁定的同一版本上按不同检查维度并行 |
| 独立审片 | 当前完整待审导出或内部预览、实际混音/原声 → 带时间码的问题、复审及是否可标为合格成片的结论；另行高质量导出时核实编码一致性与回归证据 | 与制作分离；可请求专项证据，不能以作者结论代替审阅 |

主剪串联依赖：先看原片和听原声，再找故事；故事方向明确后搜集填补实际缺口的素材；分镜和镜头筛选后才安排转场、文字、贴纸与音乐。粗剪锁定后做声音和视觉精修，可从剪映导出完整待审预览供独立agent实际查看和听音；修复复审通过并完成当前编码检查后才标为合格成片。变更时间轴的协作者不能同时写同一工程；所有人只修改各自明确分配的文件。

优先复用已看过的素材日志、已核验的许可和已有通过版本的证据。修改当前版本后，旧审片通过结论不能自动继承。大项目可分段审阅，但标为合格成片前仍须对**同一完整当前版本**完成全片顺序播放与声音审阅；原生待审导出或低清审片拷贝放工作目录并标待审，不提前混入合格成片目录或宣称交付。

## 先预检审片能力

启动独立审片前，核实当前工具和该agent实际能否：完整顺序查看运动画面、听到完整实际音轨、访问当前版本，以及对成人高风险段逐帧检查。不能因工具名称、文件可读、播放器会出声或声波可见就推断agent能看/听。已知缺少听音或完整播放等必需能力时，记录具体缺项及 `independent_review_pending`，报告待审并结束本轮审片；不长时间轮询等待、不反复生成同类导出、不反复启动同样无能力的agent。

可以单独完成已具备能力的技术检查、音量测量或局部头像复核，并标明覆盖范围和未审项目；这些结果不能当作全片通过。只有工具能力或可访问输入确实改变后才重试缺项，不能无依据承诺很快恢复。

## 审片与成片资格的门槛

**A．独立审当前实际声画。** 冻结当前时间轴版本，可从剪映原生导出带实际混音的完整待审预览，或提供完整可访问的内部预览。原生导出不需要先获审片通过；门槛约束的是**合格成片认定与交付**。预览必须包含当前的全部剪点、速度、取景、头像、字幕、转场、特效及音乐/音效，不能用分镜文档、局部联系表或旧成片代替。低清代理可用于叙事和声音审阅；成人遮挡、细字等风险须另提供当前时间轴同位置的足够分辨率逐帧证据，不因低清看不见就判通过。独立agent实际看完、听完并确认全部必须修复项解决，才记录 `agent_approved`；缺少完整预览、听音或必要逐帧能力则 pending，按能力预检规则停止本轮，不放宽门槛。

**B．交付编码检查与必要回归。** 记录拟交付文件hash、规格及当前已审版本。若独立agent已完整审查同一实际编码且达到交付规格，可将该文件从待审晋级为合格成片，无须为了“正式”二字再次导出；全片解码、规格与高风险检查仍须完成。若先审低清/内部预览再另作高质量导出，独立审片人须核实实际编码的完整播放/听音、全片解码与规格证据，并复检头像、字幕、转场、音画同步、音量和头尾，确认其镜头顺序、时长、速度、取景、文字/效果和混音与已审版本一致。代理hash与拟交付文件hash本来不同，不能凭hash不同判内容改变，也不能凭名字相同推断一致；需要时间轴版本及实际声画对照。未完成检查或必要回归不得当作合格成片交付。需要修改剪辑、声音、头像或效果时，修改后可再导出待审预览，回到阶段A审当前新版本；单纯编码设置纠错且内容未变可重导出同一已审时间轴，再重复阶段B。

本地交付、私有云备份和平台发布分别按已有明确授权执行；独立剪辑调用不自动继承云上传或公开发布授权，不自行创建共享链接。

## 独立审片的实际输入

交接最少提供：

- 阶段A：当前剪映时间轴版本/可核对的指纹，以及完整内部预览访问方式；若用审片拷贝，给绝对路径、文件名、大小和SHA-256。注明影片目标、正式画幅/准确帧率及预览质量限制。
- 阶段B：实际拟交付MP4的绝对路径、大小、SHA-256、已通过的时间轴/预览版本和对照映射。若与阶段A为同一文件，明确记录同一hash；不能仅交作者的“与预览一致”声明。
- 简明故事意图、原片区段映射、成人出镜区段及本次改动。意图用于理解目标，不暗示应给通过结论。
- 完整可听音轨；需要比对现场声音时提供对应原片音频或时间码。
- 许可台账、技术检查结果以及头像/取景风险区段。作者的 QC 只作线索，不能代替独立复检。

先确认所审版本可读、版本/文件hash一致、能够查看完整影片并听到实际音轨。没有音频能力时，必须将“原声、混音、音乐与音效衔接”记为**未审**；不能从波形、响度数值或文字描述推断听感通过。不能完整播放时，不能只凭联系表判定叙事和节奏通过。未审项存在时总体为“待审”，不得认定合格或作为成片交付；按能力预检规则记录缺项并结束本轮，而非循环等待。

## 审什么，如何给出证据

按本轮创意brief的 `style_intensity` 审美目标评估：本技能默认创意第一、叙事第二，同时兼顾两者；更密集的图形、节奏、分屏或透视合成应看其统一视觉语法、动作可读性及完成度，不用纪实片的克制程度否定创意本身。用户明确要求纪实/克制时按该方向审；成人隐私、真实来源、可读性和技术边界照常检查。当前拟交付编码还须满足 [最高画质交付](production-workflow.md#最高画质交付与代理分离)，不能把已审低清代理当母版。用户只对本轮明确豁免的项目，以项目记录的原话、范围和版本为准，报告为“用户豁免”而非“通过”。不能扩大成全局免听音，也不能把对白清晰度或音乐情绪豁免推广到爆音、音画同步、许可或其他未豁免项；余下必需项能力不足仍待审。

| 维度 | 实际审阅内容 |
| --- | --- |
| 叙事与情绪 | 开头是否引出具体人物/好奇点；行动、反应与变化是否可理解；落点是否成立；外部素材是否误导为真实家庭经历 |
| 镜头与节奏 | 空间、动作方向、目光和因果是否连续；快慢变化是否有呼吸；重复镜头是否贡献新信息；B-roll 是否补充环境或情绪而非打断关键动作 |
| 文字与效果 | 人物介绍、动态排版、擦除、镂空或跟随文字等是否有叙事动机；读得清且停留足够；字幕不遮眼神；贴纸顺序符合动作与情绪，转场不过量 |
| 成人隐私 | 全部可辨认成人（含背景、反光、侧脸）是否用一致的纯动物 3D 头像可靠遮住；头像透明边、下巴、遮挡交叉、裁切边缘和转场是否漏脸；孩子真实面部不被误遮 |
| 画面 | 肤色自然、曝光和白平衡连续；全景拼缝、抖动、畸变、锐化和升采样限制是否可接受且如实记录 |
| 声音 | 实际听完：现场对话、笑声、脚步等是否保留；配乐是否抢人声；切点是否爆音或突兀；J/L cut、环境底、混响尾音、淡入淡出和换曲是否自然；音效是否对应动作且不过密 |
| 技术与素材许可 | 全片解码、真实画幅/时基、音画同步、头尾黑帧/静音、异常闪帧、导出字样；第三方素材作者、许可、署名与使用范围是否有可追溯证据 |

顺序播放整片后，在成人进出画、转头、快速运动、遮挡交叉、镜面/背景人物、贴边构图、变速及所有涉及头像的转场处，检查**当前版本足够分辨率的逐帧画面**；阶段B还须核查实际最终编码，避免预览安全而正式导出漏脸。检测器和稀疏联系表只用于定位，不能排除一两帧漏脸；没有逐帧核查到的高风险区段须标“未审”。重大修改后重新确定风险区段，不能仅复用旧时间码。

每个问题指向当前成片的时间码（必要时加帧号）、可观察现象及具体修法，例如“00:14.60–00:15.70 成人下巴进入右边缘；更换手部特写或安全裁切，再逐帧检查这一段”。不要写只有“节奏差”“再高级一点”的空泛意见。区分影响交付的必须修复项和可选审美建议。

## 修改、复审与停止条件

1. 作者收到问题后修复当前时间轴，更新版本/指纹，可重新从剪映原生导出待审预览及hash，并说明每项修改对应的新旧时间码。阶段A未通过前不标为合格成片或当作成片交付；不能修改审片记录把问题消掉。
2. 独立审片人首先核对**当前时间轴版本及预览hash（若有）**，逐项核实必须修复项，再检查修改对声音、节奏、头像和邻近剪点的影响；对当前完整预览重新顺序播放和听音。仅审旧稿不能给新版通过。阶段B核对的是正式编码hash及其已审版本映射。
3. 成人漏脸、无法解码、明显音画不同步、严重失真/爆音或许可缺口等阻断交付；叙事混乱、关键情绪被打断、装饰干扰也须修到符合故事目标。不能为尽快通过自动降低标准。
4. 所有必须修复项解决、所有必需维度有实际审阅证据，独立审片人才能通过**当前实际声画版本**；阶段B完成后才批准当前文件作为合格成片交付。“满意”指当前版本达到交付标准，不是要求个人审美无限打磨。
5. 主剪为一轮工作设置实际的时间/渲染预算并记录；默认连续两轮完整审片仍未通过时先诊断共同原因。预算耗尽或修复依赖用户输入时保留文件与问题清单，状态为“待修”或“待审”，清楚交接原因；已知不能听/看则按预检规则立即报告并结束，不等两轮。不得无穷自动渲染，也不得把停止伪装成通过；资源受限不能跳过独立审片就标为合格成片。

可自主导出用于预览/审片，无须反复询问已授权的常规取舍。阶段A及当前文件的阶段B均通过后，才可作为合格成片交付并备份，但**不得据此推断用户已确认成片 OK**。

## 最小审片任务与记录

任务可直接写成：

> 你没有参与本片制作。当前是阶段 `{A:独立审待审版本 / B:交付编码检查与必要回归}`。先核实是否能完整看/听并检查必要逐帧；已知能力缺失则列未审项，报告待审并结束本轮，不循环等待。能力具备时，请完整顺序观看并听完 `{preview_or_final_path}`，核对当前时间轴版本 `{timeline_version}` 与文件SHA-256 `{hash_if_file}`。阶段A审查叙事、节奏、文字/效果、成人隐私、画面、声音及许可；高风险段看当前高分辨率逐帧。阶段B确认同一已审编码满足交付规格，或对照已审预览检查另行编码的一致性、技术、头像及声音回归；内容修改须退回阶段A。作者意图与QC仅为背景。每项问题给时间码、观察和具体修法。只在必需项实际审阅且问题解决后通过，不把技术或局部复核当作全片通过；当前文件完成两阶段检查前不能当作合格成片。

每版只留一份精简报告，包含：`reviewer`（独立身份及未参与制作声明）、`stage`、`capabilities`（实际完整看/听/逐帧能力）、`timeline_version`、`preview/path/sha256`、`delivery_candidate/path/sha256`（阶段B填写）、`coverage`（全片播放/音频/逐帧区段及方法）、`findings`（时间码、观察、严重性、修法）、`unreviewed`、`verdict`（声画审查通过/合格可交付/待修/待审）及 `reviewed_at`。阶段B保留与阶段A映射及一致性证据；复审附上所解决问题与当前证据，不堆积空白模板或虚假评分。

## 与用户确认及清理的关系

为每条成片分开记录：`independentReview`（阶段A）、`finalRegression`（阶段B）、`userApproval`、`jianyingCloudBackup`、`driveFinalBackup` 和 `driveOriginalBackup`；这些不是互相代替的完成标记。用户未明确确认当前成片 OK 时，`userApproval` 必须为 pending，保留本地原片，即便两阶段审查和云端归档已通过。

归档与清理由总流程按 [云归档规则](../../insta-cut/references/drive-archive.md) 接续：当前用户只需在实际云目标目录核对唯一文件名一次，不下载验证或查云端内容哈希。只有用户明确确认当前成片且相应备份文件名核对完，才按明确授权范围清理；本地成片默认保留，额外清理依本次真实用户授权。独立剪辑调用未另获上传/删除授权时只交接结果。云端原片及审片/许可记录保留。
