# 从原片到可播放故事

## 看原片：画面和声音一起建立素材地图

先检查下载完整性和实际规格；生成低清带源文件名/镜头号/时间码联系表，围绕动作与对话看连续片段。联系表只用于定位，不代替观看。听懂台词再写逐字字幕；ASR低置信、听不清的词不能脑补。记录：源in/out、动作/目光、原声、景别、运动方向、情绪变化、成人轨迹、可裁比例、原始帧率、质量风险。

容器、双镜头/音频尾部和文件稳定性确认后，剪辑开始前建立原片/侧车的唯一文件名与路径清单，总流程已明确授权备份时，由insta-cut按 [归档规则](../../insta-cut/references/drive-archive.md) 核对云端唯一文件名与传输队列并启动私有Drive归档；独立剪辑调用未另授权上传时仅保存来源/备份交接，不自行上传。已授权的上传和文件名核对与剪辑并行，不等最终成片。网络/登录/额度暂时阻碍备份时记pending，保留本地完整源片并继续可做的剪辑，不假称已备份。

全景同一时刻的不同取景是同一事件，不冒充先后发生；父母视角与孩子视角之间保留方向、轴线和声场。先抽低成本代理，再为选中段输出高质量取景，避免满盘中间片。

## 找素材：从真实内容里补齐表达

先从同一源片找环境全景、鞋与小手、树影、玩具、父母反应和动作余韵。需要外部图片、视频、纹理或音效时，再读 [素材来源](material-sourcing.md)。外部素材只有明确叙事职责才加入；风景不能替代缺失的真实事件证据。

## 编排脚本：一个具体变化，而不是标题串联

把故事写成“谁想做什么→做了什么→出现什么变化→最后留下什么”。可以冷开场再回溯、观察式顺叙、动作蒙太奇或声音引导；用实际素材支持的结构。先列候选故事，再选有完整动作/关系变化的一条，避免把所有可爱镜头塞进一片。

脚本/分镜共用一张镜头表即可，字段：

`shot_id | source in/out | timeline in/out | 画面动作/景别/取景 | 叙事作用 | 原声/音乐/音效 | B-roll理由 | 文字/技巧及动机 | 成人遮挡/风险 | 素材许可`

B-roll在脚本阶段提出，也可精剪时补入：先声后画建立空间、反应镜头解释情绪、细节压缩重复动作、空镜缓冲段落。不用无关库存镜头拖长片长。分镜写可执行的源时间码，缺关键镜头则调整故事而非假造。

## 分层精剪：创意优先，叙事同步发展

先在项目中落下本轮创意brief：`故事/视觉概念 | style_intensity=克制/平衡/炫技 | 画幅/节奏目标 | 核心视觉语法 | 拟用技巧/素材 | 成人隐私风险`。默认创意第一、叙事第二，同时兼顾两者，主动提出大胆且统一的技巧组合；图形、排版和动作可成为主要观看乐趣，不要求每个效果都只承担信息解释。视觉主题和清楚的行动线同步发展，不是故事全部锁死后才补特效。用户明确要求纪实/克制时尊重，保留相应停顿和自然感；隐私、事实和可读性不因风格强度改变。用户指定的单轮验收豁免单列于项目，不修改通用质量标准。

1. **创意结构粗剪**：先做关键视觉段的短样片，并用暂去音乐和主题花字的版本辅助检查人物、行动和变化是否可理解；不要求创意段落永久退回无设计状态。必要对白保留清楚字幕，剪掉信息重复，不剪掉理解动作所需的前因和反应。
2. **节奏精剪**：给重要目光、触摸与回应留时间；连贯动作可短，情绪停顿可长。动作切、反应切、声画错位和空镜改变节奏，不以每两秒切一次作为标准。
3. **设计处理**：每个设计先写“为何此处需要它”。人物介绍放首次有意义的出场，回溯提示只在时间真正改变时出现，文字跟踪不遮脸，结尾装饰跟随动作完成。读 [技巧索引](techniques/index.md)，整片维持字体、颜色、运动方向和声音的一致语法。
4. **声音与音乐**：先对白/现场声和空间底，再选速度、音色、乐句适配的音乐。先试自然声版本判断音乐是否有帮助。换场可用环境声桥、音乐乐句收束或混响尾音；混响只给适合的尾音/转场，不能给所有对白加空间效果。
5. **调色与待审预览导出**：镜头曝光/白平衡连续，自然肤色，保护高光；检查夜景噪点和插入素材的色彩差。真实4K60与源质量限制分开记录。完成片头/尾帧、文字安全区、头像和混音后，冻结待审时间轴版本，可从剪映原生导出带实际混音的完整待审预览；低清审片拷贝也可使用，但看不清的头像/文字须补同版本高分辨率证据。待审导出只放 `work/` 并标待审，不算合格成片或成片交付。
6. **独立审当前实际声画**：先预检未参与制作的agent能否完整观看、听音及复检必要逐帧；已知能力不足就记录 `independent_review_pending`、报告缺项并结束本轮，不循环等待不可用能力。能力可用时按 [独立审片](independent-review.md) 看完当前完整待审编码或内部预览、听完混音并对照必要原声，检查故事、节奏、效果动机、成人隐私和高风险逐帧。修复后可重新导出待审版本，更新版本与hash再独立审查；仅有旧版通过、联系表、无声观看或技术/局部复核均不能当作全片通过。原生导出本身不需要等待通过，认定合格成片及作为成片交付需要通过。
7. **交付编码检查与必要回归**：核对拟交付编码对应当前已审版本、实际画幅和时基、全片解码、文字/头像/效果、黑帧、音画同步、实际声音与AAC峰值。若独立agent审的就是同一编码且满足交付规格，可直接晋级为合格成片，无须再次导出；若另作高质量导出，实际播放/听音并对照已审版本，完成高风险逐帧与声音回归，不能仅比大小或设置。发现内容错误需修改时回到步骤6审新版本；一致性和必要检查未确认不能当作成片交付。“发布”不包含未经授权的平台公开分享。

## 最高画质交付与代理分离

- 最高质量母版与轻量预览分开：代理只用于侦察/流畅编辑/低成本审片，交付前回链已选镜头的最高质量源或高质量中间片，不把代理再次放大作为母版。
- 全景拼接/重构、抠像及复杂合成尽量从高质量源一次生成可复用中间片；按本机支持、透明通道与位深需要选择高质量帧内、近无损或合适的高码率格式，控制磁盘用量，避免同一镜头反复有损导出再导入。能保留现有码流的无画面修改步骤不无故重编码。
- 最终在剪映原生导出，实际验证当前版本支持的高画质/最高画质档、目标4K画幅与准确60或60000/1001时基、适合源片和交付设备的codec、码率/质量选项及必要色彩设置。以源质量、画面运动/纹理和编码器表现选择足够高码率，不统一写死100/200Mbps，也不把选项文字当作实际编码结果。最高可用档须用当前界面/API和短样片导出验证；不支持的设置不伪造。
- 在最终编码查实际规格、全片解码、细节/块效应、暗部、渐变、字边、头像边缘、快运动、音轨与同步；审片通过但未满足最高画质交付设置的代理不能直接晋级。另作高质量编码后按独立审片规范回归。升分辨率、锐化、补帧不能恢复本来没有记录的细节，升采样及源质量限制如实记录。

## 日期组织：实际落盘与迁移

新批次示例：

```text
project/
  shooting-days/2026-10-14/
    originals/                   # 原片与侧车的规范本体或已核验现有位置索引
    finals/                      # 对应该拍摄日的成片归属/入口
  production-days/2026-10-20/
    drafts/                      # 剪映draft名称、ID及真实应用目录索引
    assets/                      # 本轮外部素材/自制图文/音频及许可
    work/previews/               # 待审原生导出；不能混入合格成片
    2026-10-20 cuts/             # 本轮合格成片/封面/交付说明
    records/                     # brief、分镜、QC、审片、备份/用户确认
```

拍摄日来自已核对的源片时间，制作日为本轮制作开始的本地日期；跨日修订沿用批次日期，跨拍摄日故事在清单列全依赖。成片可将本体留在制作日 `cuts`，拍摄日 `finals` 建相对软链/索引，或反向组织；选择一种并记录，不能复制多份却不知哪个是当前版本。草稿、代理、外部素材和待审片不能散落在无日期公共工作目录。

实际整理时先列出当前文件与引用（剪映素材路径、播放器/画廊、QC、归档清单、脚本与云端对应），选择规范位置并做迁移清单；移动后核对大小/hash，原位置建立兼容软链，更新可安全更新的索引，再在剪映实际打开草稿并检查媒体在线、预览及相关脚本可用。验证未完成则保留原有路径/副本并记待办，不宣称已整理完成。剪映真实draft留在应用管理目录，标题带制作日，在日期 `drafts` 中保存真实位置/ID索引；不直接搬走应用数据库管理的draft。旧成片保留原文件名和版本，不为统一命名覆盖/强制重命名。Drive同步路径不以unlink/移动来整理本地入口，云端目录复用与缓存释放遵守 [归档规则](../../insta-cut/references/drive-archive.md)。

每个交付保存已审时间轴版本/指纹、待审编码SHA-256（若使用）、拟交付MP4 SHA-256、两者的镜头/声音/效果映射、源依赖、规格、字幕与效果动机、许可、QC和工具分工；同一编码晋级时记录同一hash。状态区分：`editing → preview_exported / review_pending → agent_approved → final_checks_pending → final_verified → backups_pending / awaiting_user_approval → cleanup_eligible → complete`；没有导出拷贝时可从 `editing` 直接进入内部预览待审。内容修改回到 `review_pending`，缺必需审片能力则 `independent_review_pending` 并停止本轮；技术或局部检查通过不补齐全片审查。`agent_approved` 不能替代当前编码检查、用户OK或公开发布授权。用户明确确认当前成片OK且对应备份核验完成前不得删除本地原片；备份和用户确认可先后到达，但两者都不应由推断补齐。
